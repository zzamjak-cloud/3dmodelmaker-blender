# AI LowPoly ModelMaker

Codex CLI의 GPT-6 Astra로 게임용 3D 모델(프랍·건물·자연물)을 블렌더 안에서 텍스트 프롬프트로 생성하는 Blender 확장.

- GPT-6 Astra가 헬퍼 라이브러리(`lp`) 기반 bpy 코드를 1턴으로 생성하고 실행한 뒤 완료
- 아트 스타일 5종 — **로우폴리 캐주얼**(기본) / **복셀** / **귀여운 둥근** / **스타일리쉬 캐주얼** / **사실적(미드폴리)**
- 제작 모드 3종 — **오브젝트**(프롭·건물, 멀티뷰 3면도 생성, 기본) / **배경 공간**(씬 규모 선택, 배치 3단계) / **캐릭터**(원화 → 6면도 턴어라운드 → 리깅 자세 모델링 → 매핑)
- 모델링 타입 2종 — **컬러 스와치**(공유 팔레트 텍스처, Unity 드로우콜 1개) / **개별 매핑**(박스 투영 언랩 + 6면도 AI 텍스처를 모델 이름의 개별 텍스처로 베이크)
- FBX/glTF 게임엔진 익스포트, Asset Browser 등록, 변형(variation) 생성
- 참조 이미지(멀티뷰 3면도·씬 컨셉 시트·텍스처 6면도)는 OpenRouter Image API로 생성 — 모델 선택 가능 (기본 덕테이프 `openai/gpt-image-2`)
- 모델링은 `codex` CLI 구독 그대로 — OpenRouter 키가 없으면 이미지도 codex `image_gen`으로 폴백해 API 키 없이 동작

## 설치 (자동 업데이트, 권장)

한 번 등록하면 이후 새 릴리즈가 나올 때 블렌더가 자동으로 업데이트를 확인하고 알립니다. 설치는 사용자가 실행합니다.

1. 블렌더(**5.2 LTS 권장, 최소 4.2**) → Edit → Preferences → **Get Extensions** → 우측 상단 **▼ → Repositories** → **+ → Add Remote Repository**
2. URL에 아래 주소 입력 후 **Check for Updates on Startup** 체크:
   ```
   https://github.com/zzamjak-cloud/3dmodelmaker-blender/releases/latest/download/index.json
   ```
3. Get Extensions 목록에서 **AI LowPoly ModelMaker** 검색 → Install
4. 기존에 Install from Disk나 개발용 심링크로 설치한 버전이 있으면 먼저 제거 (중복 설치 방지)

이후 업데이트는 블렌더 시작 시 알림이 뜨며, Get Extensions에서 **Update All** 한 번으로 반영됩니다.

## 설치 (수동)

1. [Releases](https://github.com/zzamjak-cloud/3dmodelmaker-blender/releases)에서 zip 다운로드 (압축 풀지 않음)
2. 블렌더 → Edit → Preferences → Get Extensions → 우측 상단 **▼ → Install from Disk** → zip 선택

## 사용법

1. `codex` CLI가 설치·로그인되어 있어야 합니다. (경로 자동 탐지 실패 시 애드온 환경설정에서 절대경로 지정)
2. (선택) 환경설정 → **참조 이미지 생성**에 OpenRouter API 키를 넣으면 참조 시트를 OpenRouter로 생성합니다 → [이미지 생성 백엔드](#이미지-생성-백엔드)
3. 3D 뷰포트 사이드바(N) → **AI 모델러** 탭
4. 프롬프트 입력 (예: `낡은 나무 배럴, 금속 밴드 2개`) → **스타일** 선택 → **제작 모드** 선택 (오브젝트 또는 배경 공간) → **모델링 타입** 선택 → **[＋]**로 큐에 추가 → **전체 실행**
   (AI 호출은 환경설정의 동시 실행 수만큼 병렬로, Blender 작업은 하나씩 순차로 진행된다)
5. 완료 후 **결과물** 패널에서 FBX/glTF 익스포트, 에셋 등록, 변형 생성

생성 턴은 `GPT-6 Astra`를 요청하고 1턴으로 완료한다. 대기 중에는 `예정 모델`이, 실행·완료 후에는 실제 사용한 모델이 상태에 표시된다. Astra가 지원되지 않거나 서버가 혼잡할 때(`at capacity`)는 초기 모델 가용성 오류에 한해서만 `Codex CLI 기본 모델 (Astra 사용 불가)`로 한 번 재시도한다. 네트워크 차단이나 로그인 만료 같은 오류에는 폴백하지 않는다. 코드 실행 실패나 응답 형식 오류의 복구 재시도는 유지하며, 성공한 결과에는 후속 AI 호출을 하지 않는다. 이전 버전의 에이전트·턴 수·모델 선택 저장값은 새 생성에 적용하지 않는다.

### 헤드리스 CLI (동기 실행)

패널의 [＋] → [전체 실행] → 익스포트를 명령 한 줄로 돌린다. 같은 세션 상태머신(멀티뷰 → 생성 → 실행 오류 자기수정 → 시각 검토 → 은면·동일평면·게임레디 정리)을 그대로 쓰고, 헤드리스에서 돌지 않는 `bpy.app.timers` 대신 `core.runner.drive`가 펌프를 직접 돌린다.

```bash
./scripts/dev_run.sh --background --python scripts/lp3d_cli.py -- \
    --prompt "낡은 나무 배럴, 금속 밴드 2개" --ref ref.png --out out/barrel.glb \
    [--style LOWPOLY] [--mode OBJECT] [--review 1] [--no-multiview] \
    [--game] [--height 0.85] [--footprint 0.96] [--preview out/barrel.png]
```

- `--review N`: 시각 검토 턴 수(0~2). UI 기본은 0이지만 CLI 기본은 1 — 사람이 결과를 보지 않으므로 한 번은 렌더를 보고 고치게 한다
- `--game`: 아래 **게임용 glTF**로 내보낸다. `--height`·`--footprint`(m)는 목표 높이·최대 발판(가로·세로 중 큰 쪽)에 맞춘 균일 배율 — 둘 다 주면 작은 배율
- `--preview`: 내보낸 glb를 다시 가져와 Eevee(흰 월드 + 태양, Standard 뷰 변환)로 쿼터뷰 렌더
- 단계별 소요 시간, 턴별 토큰, 트라이 수를 출력한다. 검토 횟수·멀티뷰 값은 이 실행 동안만 바꾸고 설정 JSON에는 쓰지 않는다
- 결과 `.blend`·재료는 UI와 같이 보관 폴더에도 자동 저장된다

### 게임용 glTF (셀별 단색 머티리얼)

결과물 패널의 **게임용 단색 머티리얼**을 켜고 glTF로 내보내면(CLI는 `--game`) 공유 팔레트 텍스처 대신 면이 쓰던 팔레트 셀 색을 albedo로 가진 Principled 머티리얼(`C_<hex>`, 같은 색은 하나로 합침)로 바꾼다. UV·텍스처를 빼고 한 메시로 합치며 원점은 바닥 중앙, 정면 -Y 그대로, glTF y-up. 머티리얼 albedo로 색을 바꾸는 엔진 셰이더(머티리얼별로 다시 칠하는 Godot 게임 등)용이다. 셀 sRGB 값은 Base Color/`baseColorFactor`(선형)에 한 번만 변환해 넣으므로 엔진 임포터가 되돌린 albedo가 팔레트 PNG와 같은 색이다. 개별 매핑 머티리얼은 그대로 두고 UV도 남긴다.

### 비용 최적화 (턴 역할별 모델)

Astra는 토큰 소모가 빨라 모든 턴에 쓰면 비용이 급증한다. 한 잡의 AI 턴을 네 역할로 나누고 환경설정 [고급] **턴 역할별 모델**에서 역할마다 모델과 추론 강도(reasoning effort)를 고른다. 기본값은 형태를 처음 잡는 **생성 턴만 Astra·high**, 나머지는 `Codex CLI 기본 모델`(`~/.codex/config.toml`의 `model`, 예: gpt-5.5)·medium 이다.

| 역할 | 해당 턴 | 기본 |
|---|---|---|
| 생성 | 초기 코드 생성 · 변형 · 배경 배치 | Astra · high |
| 검토 | 시각 검토 판정 · 6면도 대조 | 기본 모델 · medium |
| 수정 | 실행 오류 자기수정 · 검토 지적 수정 · 형식 재요청 | 기본 모델 · medium |
| 플랜 | 배경 플랜 JSON | 기본 모델 · medium |

검토·수정 턴에서 비용을 더 줄이는 장치:

- **시각 검토 방식**: 기본 `즉시 수정`은 검토 모델이 렌더를 보고 바로 전체 코드를 다시 쓴다(턴 1번). `판정 후 수정`은 검토 모델이 `VERDICT: OK/FIX`와 결함 목록만 돌려주고 결함이 있을 때만 수정 모델이 코드를 고친다 — 실측(나무 배럴, 아래 표)에서는 판정이 거의 항상 FIX로 나와 턴이 둘로 늘고, resume 입력이 턴마다 다시 과금돼 즉시 수정보다 비쌌다. 검토 모델이 비싸고 결함 없음 판정이 잦은 경우에만 고른다.
- **입력 다이어트**: resume으로 이어지는 검토·대조 턴에는 직전 코드와 멀티뷰 시트·참조 이미지를 다시 싣지 않고 대화 기록을 가리킨다(세션 이어가기가 깨진 폴백에서만 다시 싣는다). 검토 렌더는 `검토 렌더 크기` (기본 512px, 텍스처 캡처 1024와 별개)로 작게 보낸다 — 이미지 토큰은 면적에 비례한다.
- **검토 생략**: 렌더 전 자동 점검(짝 없는 파트·떠 있는 파트)에 걸린 것이 없고 대조할 시트·참조 이미지도 없으면 검토 턴을 보내지 않는다(`자동 점검 이상 없으면 검토 생략`).
- **오류 수정 승격**: 실행 오류 1차 수정은 수정 모델, 그래도 실패하면 2차는 생성 모델로 올린다.
- **배경 에셋 검토 범위**: 기본은 랜드마크·대형(L) 에셋만 검토한다(`배경 에셋 검토 범위`). 소품 수십 개의 검토 호출을 아낀다.
- **토큰 로그**: 턴마다 `토큰 [역할 · 모델 · 강도] 입력 n (캐시 n) / 출력 n`을 잡 로그에 남기고, 종료 시 합계를 적는다. 어느 역할이 비용을 쓰는지 보고 라우팅을 조정한다.

실측 (2026-10-06, "낡은 나무 배럴, 금속 밴드 2개", 멀티뷰 시트 있음, 표준 티어 단가 Astra $10/$1/$50 · gpt-5.5 $5/$0.5/$30 per 1M 입력/캐시/출력):

| 설정 | 턴 | 입력 (캐시) | 출력 | 비용 |
|---|---|---|---|---|
| 전부 Astra·high, 즉시 수정, 1024px (0.45.0) | 2 | 114,592 (60,288) | 9,637 | $1.09 |
| Astra 생성 / gpt-5.5 판정+수정, 512px | 3 | 249,859 (48,256) | 11,964 | $1.57 |
| Astra 생성 / gpt-5.5 즉시 수정, 512px (기본) | 2 | 118,854 (42,112) | 7,528 | $0.77 |

검토 턴 입력의 대부분은 resume이 다시 보내는 첫 턴 기록(지침·시트·코드)이라 모델을 바꾸면 그만큼 캐시 적중이 줄어든다(Astra 검토 캐시 48,000 → gpt-5.5 13,696~21,760). 그래도 단가 차이가 커 즉시 수정 기준 약 29% 절감이다. 다만 세 결과 중 품질은 ①이 가장 나았고 gpt-5.5가 고친 ②③이 더 낫다고 보기 어려웠다 — 그래서 **검토 턴 자체를 기본 0**으로 두며, 이때 잡당 비용은 생성 턴만큼($0.31~0.40, 기존 대비 약 −65%)이다. 검토를 켜면 위 표의 ③ 설정이 적용된다.

Astra가 사용 불가로 폴백되면 그 세션의 Astra 역할은 모두 기본 모델로 간다 — 초기 턴이면 새 세션으로, 후속(resume) 턴에서 처음 Astra를 만났다면(검토·수정을 Astra로 설정했거나 승격된 2차 수정) 세션을 유지한 채 그 턴만 다시 보낸다. 검토·수정 턴의 응답 형식 위반이 반복되면 잡을 실패시키지 않고 직전 성공 결과로 마무리한다. 시스템 지침(`AGENTS.md`)은 정적인 공통 골격 → 스타일 → API 레퍼런스 순으로 쓰고, 요청별로 바뀌는 few-shot 예시는 사용자 프롬프트 끝에 두어 서버측 프롬프트 캐시 접두가 최대한 길게 맞도록 한다.

## 모델링 타입

큐 항목마다 드롭다운으로 고른다.

- **컬러 스와치** (기본): 모든 면을 공유 팔레트 텍스처의 색 셀에 매핑한다. 씬의 모든 결과가 머티리얼 하나를 공유해 드로우콜이 1개다.
- **개별 매핑**: 생성·정리가 끝난 모델을 6방향 박스 투영으로 언랩해 한 장의 0~1 아틀라스에 패킹하고, 팔레트 색이 칠해진 모델을 FRONT/RIGHT/BACK/LEFT/TOP/BOTTOM 6시점 직교 렌더(3x2 시트)로 캡처해 codex `image_gen`에 paint-over 가이드로 보낸다. 돌아온 6면도를 시점별로 잘라 모델 표면에 깊이 인식 투영해 UV 아틀라스로 베이크(CPU)하고, **모델 이름**과 같은 이름의 이미지·머티리얼을 만들어 적용한다. 팔레트 UV와 머티리얼은 제거되어 게임엔진에는 텍스처 UV 하나만 나간다. PNG는 `~/Downloads/blender/`에 `{모델 이름}.png`로 보관됐다가 결과 저장 때 결과 폴더의 `텍스처.png`로 옮겨지고(이미지 경로도 함께 바뀐다) 익스포트 시 함께 복사된다. 텍스처 크기는 환경설정 **개별 매핑 텍스처 크기**(512/1024/2048, 기본 1024)로 정한다.
  - 텍스처 단계가 실패하면(codex 없음·시트 미저장·베이크 오류) 기하는 그대로 두고 팔레트 재질로 마감하며 원인을 로그에 남긴다.
  - 투영 베이크 엔진은 [UVmapping-Blender](https://github.com/zzamjak-cloud/UVmapping-Blender)의 `texture_bake.py`를 그대로 가져온 것이다(`texturing/bake.py`, 수정 없음).

## 스타일

큐 항목마다 드롭다운으로 고른다. 스타일은 **형태 규칙·폴리 버짓·배색**과 **참조 시트 이미지의 화풍**을 함께 정한다 — 둘이 따로 놀면 시트를 보고 만든 모델이 시트와 다른 스타일로 나온다.

| 스타일 | 성격 | 모델 1개 트라이 상한 |
|---|---|---|
| **로우폴리 캐주얼** (기본) | 각진 면, 플랫 셰이딩, 채도 높은 색. 베벨 금지 | 10,000 |
| **복셀 (로블록스형)** | 같은 크기의 정육면체 격자만. 곡선·경사·변형기 없음 | 12,000 |
| **귀여운 둥근** | 전면 베벨, 부푼 덩어리, 상단이 큰 역삼각 비율, 파스텔 | 20,000 |
| **스타일리쉬 캐주얼** | 기울고 휜 실루엣, 극단적 상하 대비, 표면 디테일 다수 | 25,000 |
| **사실적 (미드폴리)** | 실제 비율·실제 치수, 과장 없음, 낮은 채도 | 60,000 |

트라이 상한은 **모델 1개 기준**이다. 배경 공간은 그 안에 에셋이 여러 종 들어가므로 씬 전체를 이 값으로 묶지 않는다.

배경 공간의 자식 에셋 잡은 부모 배경의 스타일을 그대로 물려받는다 (한 공간에서 스타일이 섞이지 않도록).

프롬프트는 공통 골격 `prompts/system_base.md`(출력 형식·실행 환경·스타일 무관 완성도 규칙)와 스타일 조각 `prompts/styles/*.md`(형태 규칙·폴리 버짓·배색·예시 코드)로 나뉘어 있고, 조립은 `core/prompts.py`가 한다. 스타일을 추가하려면 `prompts/styles/`에 md를 넣고 `core/styles.py`의 카탈로그에 한 줄 추가하면 드롭다운·프롬프트·시트 화풍이 전부 따라온다.

복셀 스타일은 프롬프트만으로 성립하지 않아 격자 헬퍼(`lp.voxel` / `lp.voxel_box` / `lp.voxel_column`)를 별도로 제공하며, 이 어휘는 복셀 스타일의 프롬프트에만 노출된다. 맞닿은 안쪽 면은 생성하지 않으므로 블록을 붙여 쌓아도 트라이가 늘지 않는다.

## 제작 모드

큐 항목마다 드롭다운으로 고른다.

- **오브젝트** (기본): 프롭·건물·자연물 단일 모델. 멀티뷰 3면도(정면/측면/상면)로 생성하고 컬러 스와치 또는 개별 매핑으로 텍스처. 원점 바닥 중앙, 단일 메시 join. 옵션으로 실행 결과를 6시점으로 렌더하고 짝 없는 파트·떠 있는 파트 자동 점검과 함께 다시 보여 주는 **시각 검토 턴**을 돌릴 수 있다(환경설정 [고급] `오브젝트 시각 검토 횟수` · `배경 에셋 시각 검토 횟수`, **기본 0**). 실측에서 검토가 품질을 올린다고 보기 어려웠고 저렴한 모델의 수정은 오히려 나빠지기도 해 기본은 생성 1턴으로 끝낸다. 쓰려면 검토·수정 모델을 Astra로 두는 편이 낫다. 수정본이 끝내 실행에 실패하면 직전 성공 결과로 마무리한다.
- **캐릭터**: 인간형·동물형·크리처형 게임 캐릭터. **원화(참조 이미지)** 를 넣으면 그 캐릭터를 3x2 **턴어라운드 시트**(정면 | 뒷면 | 좌측면 / 우측면 | 상면 | 3/4뷰, 리깅용 중립 자세)로 먼저 전개한다. 이후 경로는 두 가지다:
  - **이미지→3D 셰이프 (기본, 셰이프 서버 필요)**: 시트의 정면 한 칸을 잘라 셰이프 서버(TRELLIS.2 — 각자 자기 Modal 계정에 배포하거나 로컬 GPU에서 실행, 아래 "캐릭터 셰이프 서버" 참고)에 보내 **셰이프와 PBR 텍스처를 한 번에** 받는다. 리메시·데시메이트·UV 언랩·텍스처 굽기까지 서버가 끝내므로 애드온은 결과를 키(기본 1.8m)·발바닥 z=0 으로 정규화해 씬에 올리기만 한다 — 별도의 리토폴로지·6면도 매핑 단계는 없다. 임포트 때 두 가지만 손본다. ① 서버 메시에 남은 작은 열린 루프(키 대비 둘레 30% 이하, 주로 부츠 옆면)를 메운다 — 8자로 맞닿은 루프는 정점을 쪼개고, 면 방향은 옆 면 다수결, 가운데 정점 부채꼴로 메워 UV 는 옆 면에서 옮긴다. ② **PBR 색을 원화에 맞춘다**(환경설정 `PBR 색을 원화에 맞추기`, 기본 켜짐) — TRELLIS.2 텍스처는 공식 설정에서도 노랑 → 황토/주황, 피부 → 연어색처럼 색조가 틀어지므로, 정면 광선으로 모은 텍셀 색과 서버에 넣은 정면 원화의 같은 자리를 짝지어 3x3+편향 변환을 맞추고 텍스처 전체에 적용한다(실측: 원화 대비 정면 오차 28.8 → 15.9, 약 1초). 무늬·눈 위치는 TRELLIS 가 다시 그리므로 원화를 직접 투영하지는 않는다. ③ 러프니스 하한(0.45)을 올린다 — TRELLIS 가 머리카락·피부에 낮은 러프니스를 줘 녹은 플라스틱처럼 번들거렸다. 정면 원화를 텍스처에 직접 투영하는 방식은 시험했으나(v0.49 개발 중) 형상과 원화가 조금만 어긋나도 엉뚱한 자리에 그려져 넣지 않았다. 끝나면 솔리드 뷰포트를 텍스처 표시로 바꿔 PBR 이 바로 보이게 한다.
  - **코드 모델링 (폴백)**: 서버가 없거나 셰이프 생성이 실패하면 시트를 보고 Astra가 리깅 자세로 코드 모델링하고, 실행 결과를 시트와 같은 6시점으로 렌더해 **시트와 대조하는 턴**을 돌려 빠진 요소·비율·떨어진 파트를 고친다(환경설정 `캐릭터 6면도 대조 횟수`, 기본 1).
  - 원화가 없으면 프롬프트만으로 시트를 만든다.
  - **캐릭터 유형** 드롭다운(자동 / 인간형 / 동물형 / 크리처형)이 비율·골격 규칙을 정한다 — 자동이면 요청문·원화에서 판단한다. 인간형은 두신 비율(원화·요청문이 정함)과 A-포즈(양팔을 45도 아래로), 동물형은 실제 골격 비율과 관절 방향(앞다리 팔꿈치 뒤·뒷다리 무릎 앞), 크리처형은 동물 부위 조합이되 하나의 골격 논리.
  - 시스템 프롬프트(`prompts/system_character.md`)는 리깅을 전제로 한다: A-포즈/네 발 중립 자세, 정면 -Y, 발바닥 z=0, 중심선 X=0, 반쪽 모델링 + `lp.mirror_x`, **관절 단위 파트 분할**(머리/목/가슴/골반/상완/하완/손/대퇴/하퇴/발), 파트 사이 0.05m 틈, 머리·얼굴에 트라이 25~35%, 장비는 별개 오브젝트로 join 허용. 시트와 요청문이 다르면 시트가 이긴다.
  - 얼굴·의상 디테일은 **개별 매핑**이 유리하다(패널에 힌트 표시). 캐릭터 모드에는 **스타일 드롭다운이 없다** — 셰이프 서버가 항상 최고 품질로 만들고, 정면 원화도 로우폴리 화풍이 아닌 고품질 컨셉 원화 문구로 고정된다. 비율은 원화(또는 요청문)가 정한다.
- **배경 공간**: 게임 씬. 씬 규모를 고르면 3단계로 진행된다:
  1. **플랜 턴**: Astra가 지형(또는 실내 껍데기)·구역·에셋 목록·씬 팔레트를 JSON으로 설계
  2. **에셋 키트**: 목록의 고유 에셋을 기존 오브젝트 파이프라인으로 병렬 생성 (랜드마크만 멀티뷰 사용)
  3. **배치 턴**: Astra가 키트를 받아 구조물·인스턴스 배치 코드 생성 후 실행

  배경 모드는 머티리얼을 **컬러 스와치**로 고정한다. 개별 매핑 선택지는 노출되지 않는다. 인스턴스는 공유 메시를 유지해 드로우콜을 최소화하고, 실패 에셋은 제외하고 계속 진행한다 (절반 초과 실패 또는 랜드마크 전멸 시만 전체 실패).

### 캐릭터 메시

캐릭터는 **하나로 병합된 단일 메시**로 만든다. 부위(몸체·의상·무기)를 따로 생성해 조합하는 모드는 0.22.0에서 제거했다 — 부품마다 이미지를 다시 그리고 3D 를 따로 재구성하면 형태·비율·디테일이 서로 어긋나 통합 생성보다 품질이 확연히 낮았다(실측, 여러 접근으로 재시도 후 철회).

메시 최적화(속 채움 리메시·데시메이트·UV 언랩)와 PBR 텍스처 굽기는 모두 셰이프 서버가 처리한다(`scripts/trellis3d/solid_remesh.py` + TRELLIS.2 공식 언랩·굽기 규약). 면수는 환경설정 없이 항상 최대 품질(삼각형 200,000, `core/shapegen.SHAPE_FACE_COUNT`)로 요청한다 — 최종 면수는 리토폴로지가 정한다. 생성이 끝난 뒤 [결과물] 패널의 **[리토폴로지 시작]** 버튼으로 쿼드 메시(QuadriFlow)를 다시 깔고 서버가 구운 PBR 텍스처를 베이크로 옮길 수 있다(0.30 계열에서 부활). X 대칭을 켜면 양의 반쪽만 깔고 미러로 용접해 좌우가 정확히 같은 와이어가 나온다. 단, 원본이 좌우 비대칭(자세가 다른 캐릭터, 한쪽에만 무기)이면 미러한 쪽이 원본에서 떨어져 텍스처가 검게 구워지므로 대칭 대신 **좌우 분할**로 깐다 — 양의 반쪽과 음의 반쪽을 각각 X=0 경계를 보존해 QuadriFlow 로 깔고 중앙선에서 정점 용접한다(정점 수 차이만큼만 삼각형). 좌우 와이어는 다르지만 얼굴·몸통 가운데를 지나는 **중앙선(X=0) 루프**는 남고 양쪽 흐름이 거기에 정렬된다. X 대칭을 끈 경우에도 모델이 X=0 에 정렬돼 있으면 같은 좌우 분할로 깐다(그냥 전체를 한 번에 깔면 중앙 앵커가 없어 가운데 와이어가 들쭉날쭉했다). 비대칭 판정(뒤집은 정점이 베이크 광선 거리 밖으로 벗어나는 비율 3% 초과)은 토글 옆 안내와 완료 상태 줄("X 대칭 꺼짐(원본 비대칭 19%)")에 보인다. 목표 면수와 X 대칭은 버튼 옆에서 고른다. **폴리시**(기본 0.5, 0 이면 끔)는 마지막에 결과의 찌글찌글한 면을 부피를 지키는 라플라시안으로 편다 — 슈링크랩이 셰이프 서버 원본의 잔요철을 그대로 받기 때문이다(FST ForgePolish 처럼 하드 엣지는 지킨다). 이면각 40° 넘는 하드 엣지 정점·엣지 선 정점·경계 정점은 고정하고, 대칭 결과는 중앙 정점을 X=0 에 다시 묶는다. 텍스처는 그 뒤 베이크로 원본에서 옮긴다. 실측(메카닉 4,000면, 고정되지 않은 정점): 표면 거칠기 0.105 → 0.044(0.5) · 0.036(1.0) 엣지, 원본에서 평균 0.13 · 상위 10% 0.27 엣지(약 5mm·1cm) 들어감, 엣지 선 커버리지·쿼드 비율 유지. **원본은 건드리지 않는다** — 원본을 복제해 `<컬렉션>_리토폴로지` 컬렉션에 `<이름>_리토폴로지` 로 깔고, 원본과 겹치지 않게 원본 폭의 1.25배만큼 +X 로 옮겨 나란히 둔다. 옵션을 바꿔 다시 누르면 지난 결과만 지우고 원본에서 새로 깐다.

생성이 끝나면 잡 정보(프롬프트·제작 모드·캐릭터 유형·스타일·원화/시트/텍스처 경로·모델·코드·로그)를 **결과 컬렉션과 원본 메시의 커스텀 프로퍼티 `lp3d_gen`(JSON)** 에 새긴다. 생성 큐는 씬 값이라 결과만 담아 저장하는 자동 저장 `.blend` 에는 따라가지 않는데, 이 파일을 열면 새겨 둔 정보로 **큐 항목이 완료 상태로 되살아나** 리토폴로지·익스포트를 다시 쓸 수 있다. 이 기능 이전 버전에서 저장해 정보가 없는 파일은 메시를 선택하고 [결과물] 패널의 **[선택 메시를 결과로 등록]** 을 누르면 된다.

셰이프 서버(v0.42.0~)는 **속을 채운 한 겹**을 보낸다(`scripts/trellis3d/solid_remesh.py`): TRELLIS.2 가 디코드한 원본 등위면을 부호 없는 거리 띠로 감싸던 공식 리메시 대신, 1024 격자 꼭짓점마다 26 방향 광선 탈출 수로 안/밖을 정한 **부호 있는 거리장**을 같은 듀얼 컨투어링 커널로 등위면 추출한다. 안쪽 껍질이 없으니 데시메이트가 두 겹을 서로 뚫지 않고, 등위면 찢김은 판정 경계를 따라 막힌다(큰 찢김일수록 캡이 안쪽으로 움푹하다). 텍스처는 원본 등위면의 가장 가까운 점에서 속성 볼륨을 샘플해 캡도 가장자리 색을 받는다. 속 채움이 실패하면 공식 경로로 돌아가는데, 그 메시는 바깥 껍질 바로 뒤(4mm 안팎)에 안쪽 껍질이 붙은 **속 빈 이중 껍질**이다. 임포트는 어느 쪽이든 안쪽 껍질을 지우지 않는다 — 바깥에서 보이지 않고, 지우면 옷과 몸 사이 좁은 틈에 구멍이 뚫린다. 리토폴로지는 먼저 **속 채우기**(`lowpoly/solid_fill.py`)로 입력을 한 덩어리로 만든다(한 겹이면 속만 채워지고, 두 겹이면 함께 녹는다): 표면을 6mm 격자의 벽으로 찍고, 1cm 이하 찢김 입구를 닫힘(팽창 후 침식)으로 막은 뒤, 바깥에서 닿지 않는 칸을 모두 속으로 채운다. 셔츠 찢김처럼 닫힘보다 넓은 찢김으로 몸속이 바깥과 이어진 모델은 흘려 넣기가 몸속까지 바깥으로 보므로, **26 방향(축·대각) 중 바깥이 보이는 방향이 3개 미만인 빈칸도 속으로 채운다** — 몸속 칸은 찢김 너머 0~1 방향만 트이지만, 다리 사이(반바지 자락 아래)·팔과 몸 사이는 아래·앞뒤로 넓게 트여 6 방향 이상이다. 6 축만 세면 앞뒤가 자락에 가린 다리 사이를 몸속과 구별하지 못해 네모난 덩어리로 메웠고, 그 덩어리가 링 가이드 단면에 섞여 다리 링이 엉덩이 바깥까지 비스듬히 그려졌다. 이 판정이 없던 v0.39 까지는 이런 모델에서 몸속이 비어 리토폴로지 면의 66~70% 가 바깥에서 보이지 않는 몸속 벽이었다(덩치큰·근육질·뚱뚱한 좀비, 지금 0.27~0.33 — 0.26 은 오목한 곳 때문에 지표의 바닥값). 링 가이드 단면 프록시도 같은 속 채우기를 거친다(팔뚝 둘레 비율 0.44 → 0.90). 쿼드를 원본에 붙이는 슈링크랩도 같은 격자로 가려낸 **바깥 면에만** 붙인다.

**엣지 선 가이드(하드 엣지·와이어 흐름).** 메카닉의 판 모서리처럼 와이어가 꼭 따라가야 하는 선이 있으면 리토폴로지 상자의 **[엣지 선 그리기]** 로 표면을 클릭해 점을 찍는다. 점 사이는 두 점과 평균 법선을 담는 평면의 단면을 따라 **표면을 타고** 이어진다(평평한 판 위면 직선, 모서리를 넘으면 모서리를 따라 꺾인다). Enter·Space·우클릭으로 선을 확정하고, Backspace·Ctrl+Z 는 마지막 점(점이 없으면 마지막 선)을, ESC 는 긋던 선을 버리거나 도구를 끝낸다. 여러 점을 이어 찍으면 곡선 흐름도 그린다. 선은 원본 표면에 붙은 열린 `LP3D_Edge` 커브로 남는다.
원리: QuadriFlow 의 sharp 제약은 입력의 이면각 60° 초과와 경계 엣지뿐인데, 속 채우기·복셀·데시메이트를 거친 입력은 모서리가 뭉개져 60° 를 못 넘는다. 그래서 선을 **입력의 경계로 바꾼다** — 선 근처 입력을 잘게 나눈 뒤 선을 따라 엣지 경로를 찾아 선 위로 옮기고, 그 경로를 갈라 얇은 렌즈 모양 틈을 낸다. 경계 보존 QuadriFlow 는 틈 양쪽에 와이어를 정렬하고, 끝나면 QuadriFlow 가 틈을 덮은 캡(정점 25개 미만 경계는 스스로 메운다)을 지우고 두 줄을 링 접합과 같은 DP 짝으로 **한 줄로 용접**해 선 위에 놓는다. 틈이 일부 닫힌 자리는 선을 따라가는 출력 엣지 사슬을 찾아 선 위로 편다. 용접한 정점은 마지막 표면 맞춤에서 움직이지 않는다. 시드마다 틈을 지키는 정도가 달라 링 접합 수와 함께 **틈을 지킨 선 수**로 출력을 고른다. 대칭 반쪽은 음의 쪽 선을 반사해 함께 깔고(겹치는 선은 하나만), 좌우 분할은 반쪽마다 따로 깐다. 반쪽 경로에서는 대칭면과 링 띠에서 출력 엣지 2개 안쪽 구간을 잘라 내므로 **중앙선(X=0)을 가로지르는 선은 가운데가 비고**, 다른 선과 교차하는 선은 뒤의 것을 건너뛴다(사유는 로그). 실측(메카닉, 목표 4,000, 좌우 분할, 12회): 선을 따라 깔린 출력 엣지 비율 — 왼 허벅지 사선 0.23 → 0.88~1.00, 중앙을 가로지르는 배 가로선 0.23 → 0.54~0.73, 가장 짧은 오른 허벅지 세로선(출력 엣지 8개 길이) 0.00 → 0.79~0.99 가 10회, 0.62 가 1회, 1회는 시드가 틈을 무시해 빠졌다(0.37) — QuadriFlow 가 비결정적이라 짧은 선이 빠지면 다시 리토폴로지하면 된다. 구멍·비매니폴드 0, 10~15초(가이드 없이 9초). 합성 구의 기운 대원호 0.18 → 0.97~1.00. 리토폴로지는 **끝점이 맞닿은 선을 한 사슬로 잇고, 한 바퀴 돌아 시작점에 닿으면 닫힌 고리**로 다룬다 — 닫힌 고리(판 외곽)는 틈이 안·밖 두 루프가 되어 링 접합과 같은 닫힌 DP 짝으로 용접한다(한 변씩 따로 다루면 모서리마다 틈 끝이 생겨 용접이 깨졌다). 시도했다가 뺀 것: 선을 평균 법선 방향 레이로 원본에 붙이기·선 3D 평활(골을 지나는 선이 표면에서 떠 커버리지 0.9 → 0~0.3), 좌우 분할에서 중앙 가로선 구간을 합친 메시에서 다시 펴기(중앙 가로선 0.7 → 0.95 였지만 가끔 구멍·비매니폴드). 뷰포트에서 가이드는 **보이는 앞쪽은 굵은 청록(엣지 선)·노랑(링), 몸에 가려진 뒤쪽은 얇은 회색**으로 그린다(깊이 오버레이). 선택한 가이드는 테마의 선택·활성 색(주황)으로 더 굵게 그린다 — 오버레이가 Blender 의 선택 강조를 덮기 때문이다. 선이 많으면(판 외곽을 짧은 선 수십 개로 이은 경우) 틈이 QuadriFlow 를 모든 밀도에서 실패시킬 수 있는데, 그때는 데시메이트로 떨어지지 않고 **틈 없이 다시 깔아 출력에서 선을 따라가는 엣지 사슬만 편다**(로그에 안내). 선은 **출력 엣지 3개 이상 길이**일 때 잘 따라간다 — 목표 4,000면이면 엣지가 약 3.7cm 라 10cm 아래 선은 정확히 담기 어렵다. 실측(메카닉, 판 외곽 선 70개, 그중 8cm 미만 26개): 목표 4,000면에서 0.7 이상 따라간 선 21개, 12,000면에서 40개(중앙값 0.81), 둘 다 쿼드 99%. 검증 `tests/verify_edge_line_in_blender.py`.

팔·다리·목처럼 원통인 부위는 곡률 앵커가 없어 QuadriFlow 가 **나선 와이어**를 깐다. 리토폴로지 상자의 **[클릭으로 링 가이드 추가]** 를 누르고 그 부위 표면을 좌클릭하면, 클릭 점을 지나는 평면들 중 단면 둘레가 짧은 방향으로 부위를 찾은 뒤, 그 단면 주변 면 법선이 가장 수직인 방향(법선 공분산의 최소 고유벡터)으로 축을 바로잡아 관에 수직인 실제 단면 링(`LP3D_Ring` 커브)을 만든다 — 최소 둘레만 쓰면 팔뚝·반바지 통처럼 굵기가 변하는 부위에서 가는 쪽으로 기울어진다(Ctrl+Z·Backspace 로 마지막 링 취소, 우클릭·ESC 로 종료). 축 자동 추정이 어긋나는 자리(어깨·사타구니처럼 이웃 부위와 붙은 곳)는 **[선 긋기]** 로 Knife 처럼 뷰에서 부위를 가로지르는 직선을 드래그하면, 그 선과 보는 방향이 이루는 평면을 절단면으로 쓴다 — 화면에 그은 기울기는 그대로지만, 보는 방향은 **가장 가까운 월드 축으로 맞춘다**(축 정렬 직교 뷰에서 그은 것과 같다). 원근·비스듬한 뷰의 평면은 시점을 지나 카메라 고도각과 부위의 좌우 위치만큼 화면에서 보이지 않게 기울고(실측 메카닉: 가이드 10개가 수직에서 3~17°), 기운 링은 경계 앵커라 주변 와이어를 같이 기울여 링 쪽으로 쏠린 듯 보였다(v0.43.0). 평면이 반대쪽 다리·몸통까지 자르므로 선을 따라 쏜 레이가 가장 많이 맞은 단면 루프를 고른다(Ctrl 로 15° 스냅, 우클릭은 긋던 선만 버림). 붙은 두 허벅지처럼 드래그 범위 밖으로 단면이 이어지면 범위 밖을 잘라 내고, 그런 링은 리토폴로지 입력 표면에 없으므로 두 부위 틈이 추정 출력 엣지 2개 이상 벌어지는 가장 가까운 높이로 가이드를 자동으로 옮긴다(그 높이는 QuadriFlow 가 틈을 건너 잇지 않는다). 리토폴로지는 가이드 자리의 입력 단면이 이웃 부위와 합쳐져 있으면 축을 따라 옮겨 자르고, 링 둘레·간격으로 필요한 최소 목표 면수(패널 표시)를 계산해 모자라면 올린다. 접합이 실패하면 가이드를 빼기 전에 목표 면수를 1.5배씩 두 번까지 올려 보고, 실패가 줄지 않으면 원래 목표로 되돌린다. 단면은 셰이프 서버 메시가 아니라 리토폴로지와 같은 **복셀 프록시**에서 자른다 — 원본은 셸이 수천 개이고 열린 테두리가 있어 단면이 닫히지 않는다. 가이드를 선택하면 **축 오프셋**으로 축을 따라 옮겨 다시 자르고, 절단면 양쪽 둘레 비율을 보여 준다(0.5 미만 붉은 표시는 평면이 발등·가슴 같은 이웃 부위를 함께 지나는 위치). 리토폴로지는 각 가이드 위치에서 **얇은 띠를 지워 경계를 만든 뒤 경계 보존으로 QuadriFlow 를 돌리고**, QuadriFlow 가 막은 캡을 지운 다음 양쪽 경계 링을 쿼드 위주 브리지(정점 수 차이만큼만 삼각형)로 **다시 접합**한다 — 경계가 앵커가 되어 링 루프가 축을 따라 전파된다. X 대칭이면 음의 쪽 가이드는 양의 쪽으로 미러해 한 번만 자르고, 대칭면을 가로지르는 목 링은 열린 호로 접합해 미러가 닫는다. 링을 넣은 대칭 반쪽이 모든 시드에서 실패하면 비대칭 전체로 떨어지기 전에 링 없이 대칭 반쪽을 다시 시도한다(대칭 우선). QuadriFlow 출력을 시드 두 개까지 접합해 보고 더 많이 접합되는 쪽을 고르며, 정점 수가 다르거나 작은 구멍으로 끊긴 짝은 일반 브리지로 대체 접합한다(겹친 면·긴 면·부채꼴이 생기면 되돌린다). 그래도 실패한 가이드만 빼고 다시 깔며 사유를 로그에 남긴다. QuadriFlow 가 비결정적이라 같은 가이드라도 접합되는 링 수가 실행마다 달라질 수 있다. X 대칭을 끄면 좌우를 따로 깔기 때문에 와이어 흐름과 접합되는 링이 좌우로 같지 않다 — 좌우가 같아야 하면 X 대칭을 켜고 한쪽에만 가이드를 둬도 된다(반대쪽 가이드는 미러로 합쳐진다). 가랑이처럼 대칭면에 닿는 링은 대칭 리토폴로지에서 쓰지 않으니 축 오프셋으로 조금 떨어뜨린다. 3DRemesher-Blender 의 링 절단·클릭 가이드를 옮겨 온 것이다(`lowpoly/ring_cut.py`, `lowpoly/ring_geometry.py`, `ui/ring_guides.py`). 자동 3단계 진행(셰이프/리토폴로지에서 정지)은 없다 — 리토폴로지는 사용자가 원할 때 누르는 후처리다.

결과가 나오는 즉시 `~/Downloads/blender/<모드>/<이름>/` 폴더 하나로 저장된다 — 편집 중인 파일 경로는 바뀌지 않는다.
- 참조 이미지(`참조`/캐릭터는 `원화`), 시트(`멀티뷰`·`턴어라운드`·`정면원화`·배경은 `컨셉시트`), 셰이프 GLB, `텍스처`가 이름을 붙여 들어간다. 클립보드로 붙여넣은 참조와 시트·텍스처처럼 결과보다 먼저 다운로드 폴더 최상단에 떨어진 파일은 복사가 아니라 **옮겨** 한 그룹으로 묶고, 그 파일을 가리키던 잡 경로·이미지 경로도 새 자리로 바꾼다. 사용자가 다른 곳에서 고른 원본은 옮기지 않는다.
- AI가 만든 모든 중간 이미지(시트 원본·시점별 텍스처·6면도 가이드·캡처)도 하위 폴더 없이 `.blend` 옆에 펼친다. 배경은 에셋 키트 자식 잡의 시트와 중간 이미지(`에셋NN_` 접두어)를 함께 모은다. 작업 폴더 원본·보관본·붙여넣기처럼 한 그림의 여러 사본은 **내용 해시로 걸러 한 장만** 둔다.
- `.blend`는 **그 결과만** 담는다 — 큐에서 함께 만든 다른 결과가 섞이지 않도록 결과 컬렉션만 든 임시 씬을 써서 저장하고, 씬에서 옆으로 옮겨 둔 자리는 파일 안에서 원점으로 되돌린다. 배경은 인스턴스가 공유하는 키트 원본을 숨긴 채 함께 담는다.
- 캐릭터·오브젝트 결과 `.blend`에는 **스튜디오**가 함께 들어간다(`core/studio.py`) — 키(앞 왼쪽 위 소프트박스)·필(앞 오른쪽, 차갑고 약하게)·림(뒤 위) 면광원 3개, 바닥에서 말려 올라가는 중성 그레이 호리존트, 번들 스튜디오 HDRI(파일에 담음), 정면에서 25° 돌린 3/4 구도 카메라(캐릭터 1080x1350·85mm, 오브젝트 1200x1200·70mm), EEVEE 레이트레이싱, 색 관리 **Khronos PBR Neutral**(베이스컬러를 원화 색 그대로 보여 준다 — AgX 는 파스텔이 탁해지고 Standard 는 하이라이트가 날아갔다). 크기·거리·광량은 모델 크기에 비례한다. 임시 씬에만 세우고 쓰고 나면 지우므로 작업 중인 파일에는 남지 않는다. 그 `.blend`를 열면 애드온이 3D 뷰를 **머티리얼 미리보기 + 씬 조명·월드 + 카메라 뷰**로 바꿔 F12 렌더와 같은 그림이 바로 보인다. 배경(씬) 모드는 스튜디오를 넣지 않는다.
- `저장된 멀티뷰 불러오기`는 결과 폴더로 옮겨진 시트까지 찾는다.

**결과는 겹치지 않게 빈자리에 놓인다.** 생성 코드는 원점 기준이므로 완료 직전에 씬에 이미 놓인 것(다른 결과·사용자 오브젝트)의 평면 영역을 보고 +X 방향으로 처음 비는 자리(간격 1m 또는 결과 크기의 10%)로 옮긴다. 예전에는 레인 번호 x 4m로 Y축에 밀어서, 큐를 비우면 레인이 0부터 다시 쓰여 예전 결과 위에 앉았고 7m 넘는 결과는 옆 레인과 겹쳤다. 아직 생성 중인 잡과 숨긴 컬렉션은 장애물로 치지 않는다.

**겹친 면의 Z-fighting은 마무리 단계에서 파트를 띄워 없앤다.** 서로 다른 파트의 면이 같은 방향으로 한 평면에 겹치면 좁은 쪽 파트(벽에 붙인 패널 등)를 통째로 노멀 방향으로 모델 크기의 0.2%(1~10mm) 띄운다 — 면을 자르거나 지우지 않으므로 면 수가 늘지 않고 편집이 쉽다. 겹겹이 붙은 디테일은 한 단씩 더 띄운다. 맞댄 면(노멀 반대, 받침 위 상자의 밑면)은 두 솔리드 사이라 보이지 않으므로 건드리지 않는다. 은면 컬링 뒤에 돌고(`lowpoly/coplanar.py` 순수 기하 + `cleanup.resolve_coplanar_faces`), 메시를 공유하는 인스턴스는 움직이지 않고 상대 파트를 민다. 배경은 배치 턴이 만든 지형·벽·방·상자끼리만 정리한다.

### 씬 규모

규모는 바닥 크기만이 아니라 **무엇을 만드는가**를 정한다. 예전에는 규모가 한 변 길이만 바꿔서, 면적이 16배인 대형에 중형과 같은 밀도를 뿌리면 텅 비어 보였다.

| 규모 | 용도 | 한 변(참고) | 에셋 종류(자동) | 배치 총량 기준 | 랜드마크 |
|---|---|---|---|---|---|
| **실내** | 건물 내부 (방·홀·상점) | 약 12m | 10종 | 약 79개 | 1개 |
| **스팟** | 옥외 한 장소 (캠프파이어·우물가·노점·정류장) | 약 12m | 8종 | 약 29개 | 1개 |
| **소구역** | 건물 한두 채 + 마당 (주유소·농가 마당·골목 한 블록) | 약 24m | 12종 | 약 69개 | 1개 |
| **구역** | 건물 여러 채 + 주변 요소 | 약 40m | 16종 | 약 112개 | 2개 |
| **대규모** | 대도시·대형 성채 | 약 100m | 24종 | 약 500개 | 3개 |

**한 변은 참고 크기다.** 공간 크기를 고정하지 않는다 — 예전에는 이 값이 목표 크기로 전달돼 컨셉 시트에 "12m"가 적히고 방도 12m로 만들어졌는데, 가구는 실제 치수(소파 약 2.2m)로 나오니 넓은 바닥에 가구가 흩어졌다. 지금은 플랜이 컨셉의 공간감과 들어갈 물건의 실제 치수로 부지를 정하고(거실 4~6m, 캠프 한 곳 8~14m — 규모 값보다 작아도 커도 된다), 컨셉 시트는 치수 표기 없이 실제 비율로 그린다. 키트가 완성되면 Σ(개수 × 키트 바닥 면적) ÷ 규모별 채움 비율(실내 0.35 ~ 대규모 0.15)로 필요한 면적을 구해, 부지가 그 0.8~1.3배 밖이면 extent·outline·구역 좌표를 같은 배율로 **늘이거나 줄인다**(`scene_plan.fit_to_kit`, 0.25~3배, 모양은 컨셉 그대로). 정규화는 퇴화값(약 2.5m 미만)과 참고 크기 4배를 넘는 터무니없는 값만 막는다. 실내 배치 턴은 평면도 자리를 좌표로 옮기고 벽 붙박이 가구를 벽에 붙이도록 지시받는다.

**배치 총량 기준**은 실제 부지 면적 × 규모별 밀도(100㎡당 개수, 표의 값은 참고 크기 기준)로 산출해 플랜 턴과 배치 턴에 수치로 전달한다 — "몇 개를 깔아야 안 허전한가"를 AI가 짐작하지 않도록 한 것이다.

**실내는 지형을 만들지 않는다.** 기복 있는 땅 위에 가구가 놓이면 실내로 읽히지 않으므로, `lp.room`으로 바닥·벽을 세우고 천장은 위에서 안이 보이도록 열어 둔다. `ground_snap`도 호출하지 않는다. 컨셉 시트도 조감도 대신 **천장을 걷어낸 컷어웨이 + 평면도**로 생성된다.

**트라이 상한은 씬 전체에 걸지 않는다** (환경설정 기본값 0 = 상한 없음). 스타일이 정하는 트라이 상한은 모델 1개 기준이라 에셋이 여러 종 들어가는 배경에 그대로 씌우면 밀도를 만들 수 없기 때문이다. 특정 기기 한도에 맞춰야 할 때만 값을 넣으면 기존처럼 초과 시 밀도 축소 재요청이 돈다. 에셋 1개의 상한에는 스타일 배수가 곱해진다 (로우폴리 L 6,000 → 사실적 L 36,000).

**지면은 격자가 아니라 윤곽 다각형이다.** 예전 `lp.terrain`은 경계 상자를 격자로 덮고 윤곽 밖 칸을 지워 가장자리가 계단처럼 깨졌고, 평지에도 의미 없는 격자 면이 가득했다. 지금은 윤곽을 모서리 깎기로 다듬어 그대로 테두리로 쓰고, `relief=0`이면 윗면 한 장, 기복이 있을 때만 성긴 내부 정점을 제약 들로네 삼각화한다(`lowpoly/terrain_shape.py`). `base`(m)는 테두리 아래 거친 두 단 바위 절벽 받침(떠 있는 섬·디오라마·강가 절벽), `elevation`은 지면을 들어 올려 언덕 위 고지대를 따로 세우는 데 쓰고, `color`/`side_color`로 윗면·절벽을 따로 칠한다. 물은 지면 윤곽 밖에 낮게 깐 평지 지형이다. `lp.ground_snap`은 지형 리스트를 받아 가장 높은 면에 놓는다. 플랜 JSON의 `terrain.base`가 받침 두께를 정한다. `heights`를 직접 주면 예전 격자 경로를 쓴다.

**에셋 색은 플랜이 시트에서 읽어 넘긴다.** 키트 에셋 잡은 컨셉 시트를 보지 못하고 요청문만 받는다. 예전에는 "씬 팔레트 5색 위주로 배색"만 전달돼 RV가 길 색, 텐트·의자가 풀 색이 되어 배경에 묻혔다. 플랜의 각 에셋에 `colors`(부위별 고유색 한 줄)를 받아 에셋 요청문에 그대로 넣고, 씬 팔레트는 지면·길·절벽·물·배치 구조물에만 쓴다.

**부지는 정사각형이 아니다.** 플랜 JSON의 `scene.extent`([폭, 깊이], 비율 자유)와 `scene.outline`(6~12점 비정형 다각형)이 부지 형태를 정하고, 배치 턴은 그 윤곽을 `lp.terrain(outline=...)`으로 그대로 쓴다. 구역에는 `rotation`(도)이 있어 배치 축이 XY축에 나란하지 않다. 예전에는 규모에서 정사각형 한 변만 나와 결과가 늘 정사각형이었다.

**규칙적인 배치는 결함으로 취급한다** (계획도시를 명시적으로 요청한 경우 제외). 길·성벽·울타리 폴리라인은 `lp.meander`로 굽히고, 집·노점·덤불처럼 모여 있는 것은 `lp.place_cluster`로 광장·길목 주변에 뭉치게 놓고, `lp.place_along`에는 `spacing_jitter`/`offset_jitter`/`rotate_jitter`를 준다. `lp.place_grid`는 막사·묘지·밭처럼 실제로 격자인 것에만 쓴다. 시스템 프롬프트의 배치 예시도 정사각 성벽 + 격자 주택에서 비정형 요새 + 군집 마을로 바꿨다 — 예시가 곧 결과의 성격을 정한다.

**울타리는 `lp.fence_run`으로 만든다.** `lp.wall_run`은 속이 꽉 찬 벽면이라 울타리에 쓰면 판때기가 된다 — 기둥·가로대·세로 살대를 실제로 세우는 별도 헬퍼를 두고, 프롬프트에서 둘의 용도를 갈랐다 (`wall_run`은 성벽·건물 외벽·막힌 담장 전용).

## 캐릭터 셰이프 서버 (TRELLIS.2, 자기 Modal 계정)

캐릭터 모드의 이미지→3D 단계는 **TRELLIS.2**(MIT, 지역 제한 없음) 셰이프 서버를 쓴다. Hunyuan3D는 라이선스가 대한민국을 명시 제외하므로 쓰지 않는다. 이미지 인코더 **DINOv3**는 Meta의 DINOv3 License(상업 가능)를 따르며, 이 기능으로 만든 결과물을 배포할 때는 **"Built with DINOv3"** 표기가 필요하다. 서버는 비상업 라이선스인 nvdiffrast/nvdiffrec(렌더·텍스처 전용)과 배경제거 모델 RMBG-2.0(CC BY-NC)을 설치·로드하지 않는다.

**비용·키는 전부 각자의 것이다.** OpenRouter 키를 각자 입력하는 것과 같은 원칙으로, 저장소에는 서버 코드만 있고 어떤 서버 주소·토큰도 들어 있지 않다. 사용자는 자기 Modal 계정에 배포해 자기 주소를 받고 자기 크레딧으로 과금된다(Starter 플랜 월 $30 무료). 엔드포인트는 Modal 프록시 인증으로 잠겨 **토큰 없는 요청은 GPU 컨테이너가 뜨기 전에 거절**되므로 주소가 노출돼도 비용이 발생하지 않는다.

```bash
uv tool install modal && modal setup                      # Modal 계정 인증(브라우저)
modal secret create huggingface-secret HF_TOKEN=<HF 토큰>   # DINOv3는 게이트 모델 — HF에서 접근 승인 후
modal run scripts/trellis3d/download_weights.py           # 셰이프 경로 가중치 ~10GB를 Volume에 1회 저장(CPU)
modal deploy scripts/trellis3d/modal_app.py               # GPU 서버 배포 → 출력의 https://…modal.run 주소
```

이어서 프록시 토큰을 만들고(`modal workspace proxy-tokens create --json`, 또는 대시보드 → Settings → **Proxy Auth Tokens**), 환경설정 → **캐릭터**의 셰이프 서버 주소에 배포 주소를, 셰이프 서버 토큰에 `wk-…:ws-…`(토큰ID:시크릿)을 넣는다. 배포 확인은 `python scripts/trellis3d/smoke_test.py --url <주소> --token-file <토큰파일> --views front.png back.png left.png right.png --out shape.glb`. 로컬 GPU 머신에서 같은 서버를 직접 띄우면 주소를 `http://127.0.0.1:8081`로, 토큰은 비워둔다.

`scripts/trellis3d/server_core.py`가 계약·전처리·후처리를, `modal_app.py`가 모델 로드·추론을 맡는다. 서버는 멀티뷰 입력(`front`/`back`/`left`/`right` base64)을 받고, 시트 라벨 제거·흰 여백 정규화를 서버에서 다시 적용하며(투명·검정 여백은 판때기로 복원된다), 통합 생성에서는 파편 제거(FloaterRemover)를 적용하고 분리 생성의 `preserve_parts` 요청에서는 작은 장비도 남긴다. 출력 GLB는 glTF Y-up 규약으로 변환된다. PBR 텍스처(베이스컬러·메탈릭·러프니스)는 서버가 함께 굽는다(`texture=True`, 크기는 환경설정 `PBR 텍스처 크기`). 콜드스타트(컨테이너 기동 + 가중치 9GB 로드) 뒤에는 컨테이너가 10분 상주해 연속 시도에 재로드가 없다. 실측(L40S, 캐릭터 4뷰, 1024 캐스케이드): 첫 요청 약 3분(콜드스타트 포함), 웜 상태 생성 약 20초, GLB 약 6MB(면수 상한 40만). 건당 비용은 웜 기준 $0.01~0.02 수준이며 Starter 플랜 월 $30 크레딧 안에서 수백 건이다.

환경설정 → **캐릭터**: 셰이프 생성 켜기/끄기, 서버 주소(기본 `http://127.0.0.1:8081`), 서버 토큰, PBR 텍스처 크기(기본 2048px), 캐릭터 기본 키, PBR 색을 원화에 맞추기(기본 켜짐). 셰이프 면수는 설정 없이 항상 200,000 삼각형이다. 서버가 응답하지 않으면 패널 로그에 남기고 코드 모델링으로 폴백한다.

## 이미지 생성 백엔드

참조 시트 3종(멀티뷰 3면도 · 씬 컨셉 시트 · 텍스처 6면도)을 무엇으로 만들지 환경설정에서 고른다. 모델링 턴은 어느 쪽이든 `codex` CLI의 Astra가 담당한다.

- **OpenRouter API** (기본): [openrouter.ai/settings/keys](https://openrouter.ai/settings/keys)에서 발급한 키를 환경설정에 넣는다. 키 대신 `OPENROUTER_API_KEY` 환경변수도 읽는다. 이미지 1장에 HTTP 요청 1회만 쓰므로 codex 세션을 띄우는 것보다 토큰 소모가 훨씬 적다.
- **Codex CLI**: codex의 `image_gen` 도구로 생성한다. API 키가 필요 없다. **OpenRouter를 골라도 키가 없으면 자동으로 이 경로로 폴백한다.**

실제로 어느 경로가 쓰이는지는 사이드바 멀티뷰 상자 첫 줄 **참조 이미지:** 에 표시된다 — `OpenRouter · 덕테이프 (GPT Image 2)` / `Codex image_gen` / `Codex image_gen (OpenRouter 키 없음 → 폴백)` / `미사용`. 대기 중인 항목은 현재 설정 기준, 실행된 항목은 그때 실제로 쓴 값이다. 로그의 시트 생성 시작 줄에도 같은 문구가 `[...]`로 붙는다.

선택 가능한 모델 (OpenRouter Image API `/api/v1/images` 기준):

| 모델 | ID | 비고 |
|---|---|---|
| 덕테이프 (기본) | `openai/gpt-image-2` | 격자 레이아웃·지시 준수도가 가장 높다. 3면도/6면도 칸 배치가 어긋나면 베이크 좌표가 틀어지므로 기본값으로 둔다 |
| 덕테이프 2.5 선버스트 | `openai/gpt-image-2.5-sunburst` | 품질 `xhigh`/`max` 사용 가능. 느리고 비싸다 |
| 덕테이프 2.5 플레어 | `openai/gpt-image-2.5-flare` | 2.5 경량 티어 |
| 나노바나나 프로 | `google/gemini-3-pro-image-preview` | 묘사력은 높지만 격자 지시를 종종 무시한다 |
| 나노바나나 2 | `google/gemini-3.1-flash-image-preview` | 빠르고 저렴 |
| 나노바나나 2 라이트 | `google/gemini-3.1-flash-lite-image` | 가장 저렴, 1K 고정 |

모델마다 지원 파라미터가 다르다(gpt-image 계열은 `quality`, Gemini 계열은 `resolution`). 지원하지 않는 값은 요청에서 빠지거나 지원 범위로 맞춰진다 — 모델을 추가할 때는 `https://openrouter.ai/api/v1/images/models`의 `supported_parameters`를 실측해 `core/imagegen.py`의 카탈로그에 옮긴다. 추측해서 넣으면 400이 난다.

API 키는 Blender 설정 폴더의 `lp3d_settings.json`에 평문으로 저장된다(다른 설정과 같은 파일). 공용 PC에서는 환경변수 쪽을 쓰는 편이 안전하다.

## 팔레트 텍스처

모든 생성 모델은 고정된 256x256 팔레트 텍스처 하나를 공유한다. 색은 Oklab
좌표에서 공식으로 결정되므로 생성 순서와 무관하게 항상 동일하다 — 덕분에
에셋 라이브러리에서 머티리얼만 교체해도 색이 그대로 유지된다.

레이아웃은 셀 4x8px, 64열 x 32행(2048색)이다. **열(좌→우) = 색상**: 무채색 4열
(그레이·웜 그레이·세피아·쿨 그레이) 다음에 색상 15개가 빨강→주황→노랑→…→자홍
순으로 놓이고, 한 색상은 채도 4단(선명→탁함)이 이웃한 4열 한 군집을 이룬다.
**행(아래→위) = 명도**: 텍스처 위쪽이 밝고 아래쪽이 어둡다. 손으로 UV를 옮겨
색을 바꿀 때 옆으로 가면 색상/채도, 위아래로 가면 밝기만 바뀐다.

- 텍스처: `lowpoly/LP3D_Palette.png` (자동 생성, 커밋됨)
- 색 데이터: `lowpoly/palette_data.py` (자동 생성, 커밋됨)
- 재생성: `python scripts/gen_palette.py`
- 검증: `python -m unittest tests.test_palette -v`

두 아티팩트는 직접 수정하지 않는다. 팔레트 공식을 바꾸면 기존에 만든 모든
에셋의 색이 바뀌므로 파괴적 변경으로 취급한다.

### 실제 Blender에서 팔레트 검증

`bpy`가 필요해 일반 유닛 테스트로는 닿지 않는 부분(이미지 pack, 구버전 `.blend`
업그레이드, 텍셀 색 일치)을 헤들리스로 검증한다.

```powershell
.\scripts\dev_run.ps1 -Background -PythonFile tests\verify_palette_in_blender.py
```

`RESULT: ALL PASS`가 나와야 한다. macOS는 `./scripts/dev_run.sh --background --python tests/verify_palette_in_blender.py`.

### 실제 Blender에서 은면 컬링·기하 검증

애드온 설치 없이 factory Blender로 바로 돈다 (`lowpoly` 패키지를 직접 임포트).

```bash
blender --background --factory-startup --python tests/verify_cull_in_blender.py      # 은면 판정 (보이는 면 보존·파묻힌 면 삭제)
blender --background --factory-startup --python tests/verify_coplanar_in_blender.py  # 동일평면 겹침 띄우기 (Z-fighting·면 수 불변)
blender --background --factory-startup --python tests/verify_geometry_in_blender.py  # 대칭도 등 QA 지표
blender --background --factory-startup --python tests/verify_texturing_in_blender.py # 개별 매핑: 언랩·6면도 렌더·베이크·재질 교체
blender --background --factory-startup --python tests/verify_voxel_in_blender.py     # 복셀 격자 헬퍼 (좌표·은면 제거·닫힌 메시)
blender --background --factory-startup --python tests/verify_sceneprops_in_blender.py # 실내 방(room)·울타리(fence_run) 구조
blender --background --factory-startup --python tests/verify_organic_in_blender.py    # 비정형 지형(outline)·meander·place_cluster·place_along 지터
blender --background --factory-startup --python tests/verify_hull_in_blender.py       # 단일 껍질 헬퍼(silhouette·loft·cut·emboss·attach·closed tube)·mirror_x 이음새·유니온
blender --background --factory-startup --python tests/verify_cut_in_blender.py        # cut 회귀: 띠·틀 문 위 얇은 홈이 몸통을 지우거나 벽을 홈 색으로 칠하지 않음, 비정상 결과는 건너뜀
./scripts/dev_run.sh --background --python tests/verify_color_match_in_blender.py -- <셰이프.glb> <정면원화.png>  # PBR 임포트: 열린 구멍·UV 겹침 없음·색 보정·러프니스 하한
./scripts/dev_run.sh --background --python tests/verify_studio_in_blender.py -- <모델.glb> <출력 폴더>   # 결과 .blend 스튜디오: 작업 파일 잔여 없음·카메라·조명 3·HDRI 담김·렌더
./scripts/dev_run.sh --background --python tests/verify_game_export_in_blender.py    # 게임용 glTF: 셀별 단색 머티리얼·선형 색·UV 제거·한 메시·바닥 중앙·정규화
```
