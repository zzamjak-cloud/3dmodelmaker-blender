# 수동 테스트 시나리오

사전 준비: Windows는 `.\scripts\dev_run.ps1`, macOS는 `./scripts/dev_run.sh`로 격리 개발 Blender 실행 → Edit > Preferences > Add-ons > **AI LowPoly ModelMaker**를 펼쳐 CLI 경로와 모델 설정 확인 → 3D 뷰포트 사이드바(N) > **AI 모델러** 탭.

1. **프랍**: 프롬프트 "낡은 나무 배럴, 금속 밴드 2개", 반복 1 → 1턴 생성, 800트라이 이하, 플랫 셰이딩 확인.
2. **건물**: "굴뚝 있는 작은 오두막", 자동 반복 3 → 턴마다 비율/디테일 개선되는지 로그와 결과 비교.
3. **자연물**: "로우폴리 소나무 3그루 스캐터" → 생성 코드가 `lp.scatter`/`lp.cone` 헬퍼를 쓰는지 로그 확인.
4. **오류 회복**: 임의 프롬프트 실행 중 로그에 "실행 오류(재시도 …)"가 떠도 최종 성공하는지.
5. **취소/재실행**: 생성 중 취소 → 씬에 잔여 오브젝트/컬렉션 없음 → 즉시 재실행 정상.
6. **익스포트**: 배럴을 FBX로 내보내 Unity 임포트 — 스케일 1, 원점 바닥 중앙, 단일 머티리얼, LP3D_Palette.png 동봉. glTF는 validator 통과.
7. **에셋**: "에셋 등록" → Asset Browser에서 LowPoly/Props 카탈로그와 프리뷰 확인.
8. **변형**: "변형 생성" 3개 → 원본과 구별되면서 스타일 일관성 유지.
9. **에이전트 패리티**: 시나리오 1을 Claude/Codex 각각 실행해 동일 파이프라인 동작 확인.
10. **CLI 미설치 경로**: 환경설정 경로를 비우고 CLI가 PATH에 없을 때 명확한 오류 메시지 확인.
11. **팔레트 고정**: 서로 다른 프롬프트로 모델 2개 생성 → 각각 FBX 익스포트 → 두 폴더의 `LP3D_Palette.png`가 바이트 단위로 동일한지 확인 (`cmp` 또는 해시 비교). 리포의 `lowpoly/LP3D_Palette.png`와도 동일해야 한다.
12. **머티리얼 교체**: 생성한 모델의 머티리얼을 에셋 라이브러리의 팔레트 머티리얼로 교체 → 색이 그대로 유지되는지 확인. 전제: 라이브러리 텍스처가 `lowpoly/LP3D_Palette.png`와 동일하고, 노드 설정이 Closest 보간 / sRGB / Roughness 0.9여야 한다.
13. **구버전 .blend 열기**: v0.4.x로 만든 `.blend`를 열고 생성 실행 → 팔레트 이미지가 고정 팔레트로 교체되고, 머티리얼 노드 연결이 끊기지 않는지 확인. 기존 모델의 색은 바뀐다(의도된 파괴적 변경).
14. **한글 입력 팝업**: mac/Windows 각각 — [프롬프트 입력] 버튼 → OS 네이티브 팝업에서 한글 입력(띄어쓰기 1회로 정상 입력되는지) → [입력완료] 시 필드 반영. 취소 시 기존 값 유지, 빈 문자열로 완료 시 필드 비워짐, 기존 값이 팝업에 프리필되는지, 개선 UI의 [개선 프롬프트 입력] 버튼도 동일 동작하는지 확인. Windows는 콘솔 창이 뜨지 않아야 한다.
15. **조기 DONE 무시**: 자동 반복 3으로 생성 시 에이전트가 1~2턴에 `STATUS: DONE`을 내도 로그에 "최소 턴 전 DONE 선언 무시"가 찍히고 3턴까지 도는지 확인. 개선하기 버튼(1턴)은 DONE 즉시 종료가 정상.
16. **배치 실행 병렬성**: 프롬프트 3개("나무 상자", "돌 항아리", "철제 랜턴")를 [＋]로 큐에 추가 → [전체 실행] → 요약 줄에 `AI 실행 3`이 뜨는지, 작업 관리자/`ps`에서 CLI 프로세스가 3개인지 확인. 환경설정 "동시 AI 실행 수"를 1로 낮추면 `AI 실행 1 · 대기 2`가 되는지도 확인.
17. **Blender 직렬화**: 위 상태에서 여러 항목이 동시에 EXEC/CAPTURE 단계에 들어가지 않는지 확인 — 요약 줄의 `Blender 대기`가 늘었다 줄고, 렌더가 겹쳐 깨지거나 컬렉션이 뒤섞이지 않아야 한다. 결과 3개가 Y축으로 4m씩 벌어져 나란히 놓이는지 확인.
18. **부분 실패 격리**: 항목 하나의 에이전트를 CLI가 설치되지 않은 쪽으로 바꿔 [전체 실행] → 그 항목만 빨간 `실패`로 남고 나머지 2개는 정상 완료되는지, [재시도] 버튼으로 되살아나는지 확인.
19. **항목 단위 중단**: 3개 실행 중 하나를 선택해 [항목 중단] → 그 항목만 `취소됨`이 되고 씬에 잔여 오브젝트가 없으며, 나머지 2개는 계속 진행되는지 확인.
20. **실행 중 항목 삭제**: 실행 중인 항목을 [－]로 삭제 → 크래시 없이 해당 CLI 프로세스가 종료되고 나머지 큐가 계속 도는지 확인.
21. **Dev Reload 교착 해제**: 실행 중에 [Dev Reload] → 모든 세션이 정리되고, 리로드 후 `RUNNING`으로 남은 항목이 `대기 중 (세션이 끊겨 초기화됨)`으로 바뀌어 [전체 실행]이 다시 눌리는지 확인.
22. **선택 항목 기준 결과물**: 완료된 항목 3개를 번갈아 선택하며 [FBX 익스포트]/[에셋 등록]/[개선하기]가 각각 선택한 항목의 컬렉션을 대상으로 동작하는지 확인. [변형 생성]은 새 큐 항목으로 추가되어 원본을 덮지 않아야 한다.
23. **큐 자료구조 헤들리스 검증**: `.\scripts\dev_run.ps1 -Background -PythonFile tests\verify_queue_in_blender.py` (macOS는 `./scripts/dev_link.sh` 후 `blender -b --python tests/verify_queue_in_blender.py`) → 전 항목 PASS, 마지막 줄 "모두 통과". AI CLI 없이 도는 부분(잡 추가·복제·정렬·삭제, 레인 배치 멱등성, 시작 거부, reset_stale, shutdown)의 회귀를 잡는다. 16~22는 실제 생성이 필요하므로 이걸로 대체되지 않는다.

24. **Astra 모델 표시**: Edit > Preferences > Add-ons > **AI LowPoly ModelMaker**의 **Codex 모델**을 `GPT-6 Astra`로 선택 → 사이드바에서 [＋]로 job 추가 → 항목의 에이전트 토글에서 `Codex` 선택 → 실행. 대기 중 `예정 모델`, 실행/완료 후 `사용 모델: GPT-6 Astra`, 단계 목록의 생성/비평 모델명이 모두 일치하는지 확인.
25. **Astra 가용성 fallback**: 같은 위치에서 **Codex 모델**을 `GPT-6 Astra`로 두고, Astra 접근이 없는 계정에서 Codex job의 최초 호출 실행 → 모델 가용성 오류에 한해 `Codex CLI 기본 모델 (Astra 사용 불가)`로 한 번 재시도하고 로그에 요청 모델과 실제 사용 모델이 남는지 확인. 네트워크 차단이나 로그인 만료에서는 fallback하지 않아야 한다.
26. **대표 3종 A/B**: Claude 기존 기본과 Codex + `GPT-6 Astra`에서 자동 반복 3, 캡처 앵글 4, 해상도 512, 멀티뷰 참조 생성 끔, 참조 이미지 없음, 생성 라이브러리 끔으로 설정하고 한 번에 한 job만 실행한다. 별도 seed UI는 없으므로 동일한 3턴 실행에서 executor가 seed 1/2/3을 자동 사용한다. 다음 프롬프트를 각각 생성한다: 프랍 `낡은 나무 배럴, 금속 밴드 2개와 깨진 판자 1개`, 건물 `작은 중세 대장간, 돌 기단과 큰 굴뚝`, 자연물 `굽은 소나무, 드러난 뿌리와 비대칭 수관`. 결과 표에 asset별 silhouette, 비율, signature detail, 색 분리를 출처를 가린 상태에서 각각 1~5점으로 기록하고, floating part 있음은 -2점, nonmanifold 있음은 -2점, 실행 오류 1회당 -1점(최대 -3점), 10k tris 초과는 -2점으로 합산한다. 두 결과의 asset별 총점 차이가 1점 이하면 동점으로 기록한다. Astra가 3 asset 중 최소 2개를 명확히 이겨야 채택하며 동점은 승리로 세지 않는다. 실제 비교 전에는 Astra가 더 낫다고 결론내리지 않는다. 현재 자동화 환경에서는 외부 Codex 호출이 차단될 수 있으므로 live A/B는 개발 Blender와 접근 가능한 계정에서만 수행하고, 실행하지 못한 결과는 미검증으로 기록한다.
