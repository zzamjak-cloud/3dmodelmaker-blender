# 수동 테스트 시나리오

사전 준비: Windows는 `.\scripts\dev_run.ps1`, macOS는 `./scripts/dev_run.sh`로 격리 개발 Blender 실행. 환경설정에서 Codex CLI 경로를 확인하고, 3D 뷰포트 사이드바(N)의 **AI 모델러** 탭을 연다.

1. **단일 생성**: "낡은 나무 배럴, 금속 밴드 2개"를 큐에 추가하고 실행한다. 요청 모델은 GPT-6 Astra이고, 첫 코드 실행이 성공하면 1턴에서 완료되어야 한다. 완료 후 AI 호출이나 결과 교체가 없어야 한다.
2. **대표 형태**: "굴뚝 있는 작은 오두막", "로우폴리 소나무 3그루 스캐터"도 각각 1턴으로 생성한다. 실루엣, 팔레트 색상, 플랫 셰이딩, 원점과 스케일을 확인한다.
3. **이전 설정**: 이전 버전에서 에이전트와 여러 턴을 지정했던 `.blend`와 환경설정을 열어도 새 생성은 Astra 1턴이어야 한다. 제거된 에이전트 선택·턴 설정·후속 수정 입력과 버튼이 노출되지 않아야 한다.
4. **오류 복구**: 응답 형식 또는 코드 실행 오류가 발생하면 제한된 복구 재시도 후 성공하거나 명확한 실패 상태가 되어야 한다. 첫 성공 이후에는 재시도하지 않는다.
5. **Astra 폴백**: 최초 요청의 모델 접근 불가 오류에만 Codex CLI 기본 모델로 한 번 재시도한다. 실제 사용 모델과 폴백 사유가 표시되어야 한다. 로그인 만료·네트워크 오류에는 폴백하지 않는다.
6. **취소/재실행**: 생성 중 취소하면 해당 CLI와 잔여 오브젝트가 정리되고, 즉시 재실행할 수 있어야 한다.
7. **익스포트**: FBX를 Unity로 가져와 스케일 1, 원점 바닥 중앙, 단일 머티리얼, LP3D_Palette.png 동봉을 확인한다. glTF도 내보내기를 확인한다.
8. **에셋/변형**: 선택한 결과의 에셋 등록이 동작하고, 변형 생성은 새 큐 항목으로 추가되어 원본을 덮지 않아야 한다. 각 변형도 독립적인 1턴 생성이다.
9. **CLI 미설치**: 실행 파일을 찾을 수 없는 경로에서는 명확한 Codex 설치 안내가 표시되어야 한다.
10. **팔레트 고정**: 서로 다른 결과를 익스포트한 두 폴더의 LP3D_Palette.png가 동일해야 한다. 머티리얼을 교체해도 색이 유지되어야 한다.
11. **한글 입력**: macOS/Windows 네이티브 프롬프트 팝업에서 한글·띄어쓰기·취소·빈 문자열 입력을 확인한다. Windows에서는 콘솔 창이 뜨지 않아야 한다.
12. **배치 병렬성**: 프롬프트 3개를 실행해 동시 AI 실행 수 설정이 적용되고, Blender 실행은 직렬 처리되는지 확인한다. 결과가 Y축으로 분리되고 컬렉션이 섞이지 않아야 한다.
13. **부분 실패/중단/삭제**: 실행 중 한 항목을 중단하거나 삭제해도 나머지가 완료되어야 한다. 실패 항목의 재시도는 해당 항목에만 적용되어야 한다.
14. **Dev Reload**: 실행 중 리로드하면 세션이 정리되고, 끊긴 RUNNING 항목이 대기로 돌아가야 한다. 이전 버전에서 갱신할 때도 등록 오류가 없어야 한다.
15. **모델 표시**: 대기·실행·완료 상태의 요청 모델과 실제 모델 표시가 일치하고, 폴백 결과에는 Codex CLI 기본 모델이 표시되어야 한다.
16. **개별 매핑 타입**: 항목의 모델링 타입을 `개별 매핑`으로 두고 "낡은 나무 배럴"을 실행한다. 마무리 뒤 상태가 `UV 언랩중 → 6면도 가이드 렌더중 → 텍스처 6면도 생성중 → 텍스처 베이크중 → 텍스처 적용 완료`로 진행되고, 결과 오브젝트에는 UV 레이어 `UVMap` 하나와 오브젝트 이름의 머티리얼·이미지(pack됨)가 있어야 한다. `~/Downloads/blender/{이름}.png`가 생기고 FBX 익스포트 폴더에 같은 PNG가 동봉되어야 한다. 항목 복제 시 타입이 따라와야 한다.
17. **개별 매핑 실패 폴백**: codex 경로를 잘못 지정하거나 타임아웃을 짧게 두고 개별 매핑을 실행하면, 기하는 팔레트 재질로 완료되고 상태줄에 `텍스처 실패`와 원인이, 로그에 조치가 남아야 한다. 컬러 스와치 타입 결과는 이전과 동일해야 한다.

배경 공간 모드:

18. **포로 수용소(M) 정상 생성**: 제작 모드를 `배경 공간`으로 선택하고 "중세 포로 수용소, 목재 울타리와 경비소" 프롬프트를 큐에 추가한다. 씬 규모 `M(약 40m)`을 선택하면 플랜 턴 → 에셋 키트(병렬 생성) → 배치 턴이 진행되고, 완료 후 씬 컬렉션 하위에 지형·구조물·인스턴스가 배치되어야 한다. 원본 에셋은 `LP3D_*_Kit` 컬렉션에 숨겨져 있어야 한다. 다른 큐 항목들과 렌(Lane) 간격이 씬 extent+8m으로 분리되어야 한다.

19. **고대 성(L) 트라이 예산 초과 축소 확인**: "고대 성터, 돌 성벽과 탑" 프롬프트를 배경 공간 모드로 추가하고 씬 규모 `L(약 80m)`을 선택한다. 플랜 턴에서 에셋이나 지형이 트라이 예산(기본 80000)을 초과하면, 자동 축소 경고가 로그에 남고 배치 턴이 진행되어야 한다. 배치 코드 실행 후 예산을 초과하면 Astra에 밀도 축소 재요청이 1회 발생하고, 재요청 후에도 초과하면 경고만 남기고 완료되어야 한다.

20. **에셋 일부 실패 / 부모 취소**: 배경 공간 모드에서 프롬프트를 추가하고 실행 중 일부 에셋 생성이 실패한다면, 실패한 에셋은 플랜에서 제외되고 나머지가 계속 진행되어야 한다 (절반 초과 실패 또는 랜드마크 전멸이 아닌 이상). 반대로 부모 잡을 중단/삭제하면 생성 중인 자식 잡(에셋)들이 일괄 취소되어야 한다. 최종 씬에는 성공한 에셋만 배치되어야 한다.

AI 호출 없는 실제 Blender 회귀 검증:

```bash
./scripts/dev_run.sh --background --python tests/verify_single_turn_in_blender.py
./scripts/dev_run.sh --background --python tests/verify_queue_in_blender.py
```

```powershell
.\scripts\dev_run.ps1 -Background -PythonFile tests\verify_single_turn_in_blender.py
.\scripts\dev_run.ps1 -Background -PythonFile tests\verify_queue_in_blender.py
```

자동 검증의 CLI는 대역이다. 실제 모델 품질과 계정별 Astra 접근 권한은 수동 시나리오에서 별도로 확인한다.
