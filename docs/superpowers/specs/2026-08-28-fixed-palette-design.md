# 고정 팔레트 텍스처 설계

> **2026-09-12 개정**: 셀 배치를 "행=색상 / 열=명도 / 좌우 절반=채도"에서
> "열=색상 군집(무채색 4열 + 색상 15개 x 채도 4단) / 행=명도(위가 밝음)"로 바꿨다.
> 셀은 4x8px, 64열 x 32행 = 2048색이며 텍스처 크기(256x256)와 스냅 방식(Oklab
> 최근접)은 그대로다. 아래 본문의 32x32/1024셀 서술은 개정 전 기준이다.
> 세부: docs/superpowers/plans/2026-09-12-cull-precision-palette-layout.md


작성일: 2026-08-28
대상 버전: v0.5.0

## 1. 배경과 문제

현재 `lowpoly/palette.py`는 32x32 그리드(256x256 텍스처)를 쓰지만, 셀 배정이
**등장 순서 기반**이다.

```python
cell = len(mapping)   # 에이전트가 요청한 순서대로 뒤에 쌓인다
```

그 결과:

- 생성할 때마다 팔레트 텍스처의 내용이 달라진다. 같은 색을 요청해도 다른 모델에서는
  다른 셀에 앉는다.
- 텍스처가 실행 이력에 종속되므로, 팔레트를 유실하면 기존 모델의 색을 복원할 수 없다.
- 셀 고갈 방지를 위해 스냅샷/복원, 그리드 이전, UV 재매핑 같은 가변 상태 기계가
  필요했다.
- 에셋 라이브러리의 머티리얼과 새로 생성된 머티리얼의 텍스처가 서로 다르므로,
  머티리얼 교체만으로 색을 보존할 수 없다.

실제 사용 중인 `AssetLibrary_Palette.png`를 디코딩한 결과 1024칸 중 208칸만
채워져 있고, 그중 고유색은 181개였다(부동소수 키 차이로 27개 중복).

## 2. 목표

1. 팔레트 텍스처를 **영구 고정**한다. 몇 번을 생성하든 바이트 단위로 동일한 PNG.
2. 임의의 RGB 요청을 지각적으로 가장 가까운 스와치로 **스냅**한다. 에이전트 API와
   프롬프트는 바꾸지 않는다.
3. 사용자가 에셋 라이브러리에서 **머티리얼만 교체하면 색이 그대로 유지**되게 한다.
   (UV가 동일한 셀 중심을 가리키므로 성립)

## 3. 범위 밖 (Non-goals)

- 기존에 생성된 에셋의 색 보존. 사용자가 명시적으로 불필요하다고 결정했다.
  새 팔레트 적용 시 기존 에셋의 색은 바뀐다.
- 색 이름 지정 API(`lp.set_color(obj, "wood_dark")`). RGB 지정 방식을 유지한다.
- 팔레트 그리드 크기 변경. 32x32 / 8px 셀 / 256x256을 영구 고정으로 못 박는다.

## 4. 팔레트 구조

32x32 셀, 셀당 8x8 픽셀, 총 256x256. 셀 0은 **좌하단**(Blender UV 원점 기준),
셀 인덱스는 행 우선(row-major)으로 증가한다.

| 영역 | 셀 범위 | 행 | 내용 |
|---|---|---|---|
| 무채색 | 0~63 | 하단 2행 | 순수 그레이 32단 / 따뜻한 그레이 32단 |
| 유채색 | 64~1023 | 30행 | 색상 15개 x 2행(64칸), 각 색상 = 채도 4단 x 명도 16단 |

### 4.1 생성 공식

모든 셀 색은 Oklab 좌표에서 공식으로 결정된다. 사람이 손으로 고르는 색은 없다.

- **색상(hue)**: Oklab hue를 15등분. `h_i = 2*pi*i/15` (i = 0..14)
- **명도(L)**: 0.16 ~ 0.97 균등 16단
- **채도(C)**: 절대값이 아니라 **해당 (L, h)에서 sRGB 게멋 안에 들어가는 최대 채도의
  비율** 16% / 38% / 64% / 92%. 최대 채도는 이분 탐색으로 구한다.
- **무채색 램프**: L = 0.06 ~ 0.99 균등 32단.
  - 행 0: C = 0 (순수 그레이)
  - 행 1: C = 0.018, hue 70도 (따뜻한 그레이)

채도를 비율로 잡는 것이 핵심이다. 절대 채도를 쓰면 게멋 밖 조합이 클램핑되어
같은 색이 여러 칸에 중복 생성된다(초기 시안에서 1024칸 중 860색만 고유).
비율 방식에서는 **1022칸이 고유색**이다.

### 4.2 셀 인덱스 계산

```
무채색:  cell = row * 32 + L_index                    (row = 0, 1)
유채색:  cell = 64 + hue_index * 64 + chroma_index * 16 + L_index
```

색상 하나가 정확히 2행을 차지하므로, 팔레트를 이미지 뷰어로 열었을 때 색상별
블록이 행에 맞아떨어져 육안 검수가 가능하다.

### 4.3 스냅 품질 검증 결과

임의 RGB가 최근접 스와치로 스냅될 때의 Oklab 거리(dE):

| 테스트셋 | 평균 | 90퍼센타일 | 최대 |
|---|---|---|---|
| 기존 사용 색 181개 | 0.017 | 0.027 | 0.036 |
| sRGB 전역 랜덤 3000색 | 0.027 | 0.042 | 0.084 |

참고: dE 0.02는 두 색을 나란히 붙여야 겨우 구분되는 수준이다. 후보 구성 11가지를
비교해 이 구성이 두 테스트셋 모두에서 최적이었다.

## 5. 아티팩트

`scripts/gen_palette.py` 하나가 아티팩트 2개를 생성한다. 이 스크립트는 Blender
없이 순수 파이썬(표준 라이브러리만)으로 실행되며, 외부 의존성이 없다.

### 5.1 `lowpoly/LP3D_Palette.png`

256x256, 8비트 트루컬러, 무알파. 리포에 커밋한다.

- 애드온은 이 파일을 `bpy.data.images.load`로 로드한다(픽셀을 코드로 칠하지 않는다).
- 익스포트 시에도 `img.save()`가 아니라 `shutil.copyfile`로 원본을 그대로 복사한다.
  Blender의 저장 경로를 거치지 않으므로 항상 바이트 동일하다.

### 5.2 `lowpoly/palette_data.py`

생성된 1024개 셀의 RGB 정수 튜플 리스트. 스냅 계산에 쓴다.

PNG와 같은 스크립트에서 같은 실행으로 뽑으므로 어긋날 수 없고, 테스트가 일치를
검증한다. 런타임에 PNG를 디코딩할 필요가 없다.

두 파일 모두 상단에 "자동 생성됨 — 직접 수정 금지, `scripts/gen_palette.py`로
재생성" 주석을 넣는다(PNG는 해당 없음).

## 6. `lowpoly/palette.py` 변경

### 6.1 삭제

팔레트가 읽기 전용이 되면서 가변 상태 기계가 통째로 사라진다.

| 삭제 대상 | 이유 |
|---|---|
| `_assign_cell`, `_COLORS_PROP` | 색에서 셀이 공식으로 결정된다. 등장 순서 무관 |
| `_paint_cell`, `_write_pixels` | 픽셀을 쓸 일이 없다 |
| `_migrate`, `_remap_uvs`, `_sample_cell`, `_GRID_PROP` | 그리드가 영구 고정이라 이전 개념이 없다 |
| `snapshot_state`, `restore_state` | 실행이 팔레트를 소비하지 않으므로 되돌릴 것이 없다 |
| `_nearest_cell` (RGB 유클리드 거리) | Oklab 스냅으로 대체 |
| `_new_image` (회색 채우기) | PNG 로드로 대체 |

### 6.2 추가

- `_srgb_to_oklab(rgb)` — 순수 함수. sRGB 0~255 -> Oklab 3튜플.
- 모듈 임포트 시 `palette_data`의 1024색을 Oklab으로 한 번 변환해 캐시한다.
- `_snap_cell(color)` — 0~1 범위 RGB를 받아 Oklab 최근접 셀 인덱스를 반환.
  1024개 선형 탐색. 모델당 색이 10개 안팎이라 비용은 무시할 수준이다.
- `_load_image()` — `LP3D_Palette` 이미지가 없으면 번들 PNG를 로드한다.
  이미 있으면 다음 중 하나라도 해당할 때 **교체**한다(기존 호환 불필요):
  크기가 256x256이 아니다 / 구버전 마커 `lp3d_colors` 또는 `lp3d_grid`
  커스텀 프로퍼티가 있다 / 셀 중앙 픽셀이 `palette_data`와 다르다.
  교체 시 `bpy.data.images.remove` 후 재로드하지 않고 기존 데이터블록의 픽셀만
  덮어쓴다. 머티리얼 노드의 이미지 참조가 끊기지 않게 하기 위함이다.

### 6.3 유지

`set_color(obj, color, faces=None)`의 **공개 시그니처와 동작은 그대로**다.
내부에서 `_assign_cell` 대신 `_snap_cell`을 호출하는 것만 다르다.
따라서 에이전트가 생성하는 코드도, `prompts/system_lowpoly.md`도 수정할 필요가 없다.

### 6.4 머티리얼 노드 설정 (고정)

에셋 라이브러리 머티리얼과 색이 일치하려면 다음이 어긋나면 안 된다.

- 텍스처 노드 `interpolation = 'Closest'`
- 이미지 `colorspace_settings.name = 'sRGB'`
- Principled BSDF `Roughness = 0.9`

## 7. 연쇄 변경

### 7.1 `core/executor.py`

- `snapshot()`의 `snap["_palette"] = palette.snapshot_state()` 제거
- `rollback()`의 `palette.restore_state(...)` 제거
- `rollback()`의 `images` 데이터블록 정리에서 **팔레트 이미지를 제외**한다.
  실행이 실패해도 팔레트 이미지가 지워지면 안 된다.

### 7.2 `pipeline/export.py`

`save_palette_png(directory)`를 `img.save()` 기반에서 번들 PNG의 `shutil.copyfile`로
교체한다. 함수명과 반환값(저장 경로)은 유지한다.

### 7.3 `blender_manifest.toml`

- `lowpoly/LP3D_Palette.png`가 확장 패키지에 포함되는지 확인한다.
  현재 `paths_exclude_pattern`에 `/scripts/`, `/tests/`는 있지만 `lowpoly/`는 없으므로
  기본적으로 포함된다.
- `/docs/`를 `paths_exclude_pattern`에 추가한다(애드온 실행에 불필요).

## 8. 테스트

`tests/`에 현재 수동 시나리오 문서만 있다. 아래가 첫 자동 테스트가 되며, Blender
없이 순수 파이썬으로 돈다(`bpy` 임포트 없음).

1. **재현성** — `gen_palette.py`를 두 번 실행해 PNG 바이트가 동일한지
2. **아티팩트 최신성** — 커밋된 `LP3D_Palette.png`가 스크립트 출력과 일치하는지
3. **아티팩트 동기화** — `palette_data.py`의 1024색이 PNG의 각 셀 중앙 픽셀과 일치하는지
4. **스냅 정확성** — 1024색 각각을 `_snap_cell`에 넣으면 자기 자신의 셀로 스냅되는지
5. **품질 회귀 방지** — 기존 사용 색 181개의 스냅 오차가 모두 dE 0.04 이하인지.
   기준 색 목록은 테스트 픽스처로 커밋한다.

테스트 4/5는 `palette.py`의 스냅 로직을 `bpy` 없이 임포트할 수 있어야 하므로,
Oklab 변환과 `_snap_cell`은 `bpy`에 의존하지 않는 순수 함수로 유지한다.

## 9. 사용자 워크플로우

1. 애드온으로 모델 생성 -> 고정 `LP3D_Palette.png`를 참조하는 `LP3D_Palette`
   머티리얼이 붙는다
2. FBX 익스포트 -> 동일한 PNG가 동봉된다
3. 에셋 라이브러리에서 머티리얼만 라이브러리 것으로 교체 -> **UV가 그대로이므로
   색이 100% 유지**된다

전제 조건: 라이브러리 머티리얼이 쓰는 텍스처가 리포에 커밋된
`LP3D_Palette.png`와 동일해야 한다. 현재
`D:\Project_Work\Blender\Blender_Asset_Library\Textures\AssetLibrary_Palette.png`를
새로 생성된 PNG로 교체해야 하며, 그 시점에 기존 에셋의 색은 바뀐다(2절 목표 3, 3절 범위 밖 참조).

## 10. 마이그레이션

기존 호환이 불필요하므로 별도 마이그레이션 경로를 만들지 않는다.

- `.blend`에 남아 있는 구버전 `LP3D_Palette` 이미지는 애드온이 로드 시 교체한다.
- 구버전 팔레트로 만든 모델을 다시 열면 색이 달라진다. 이는 의도된 동작이며,
  릴리스 노트에 **파괴적 변경**으로 명시한다.
- 버전을 v0.5.0으로 올린다(마이너 상향 — 기존 에셋의 색이 바뀌는 파괴적 변경).
